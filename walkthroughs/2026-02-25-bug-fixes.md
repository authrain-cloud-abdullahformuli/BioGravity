# Bug Fixes Walkthrough (2026-02-25)

## 1. Graph Navigation Buttons

**Description**: The Zoom In/Out and Reset buttons in the graph's Navigation Controls were failing to perform the intended graph manipulations. The root cause was identified inside `graph-scene.tsx`: the application's `setGraphRef` state function was inside a `useEffect` expecting `graphRef.current` to predictably trigger dependency arrays, which it does not.
**Fix**: Changed the inner element to correctly synchronize the `ref` dynamically.
**Verification**: Zoom buttons and Reset View now trigger successfully.

## 2. Pinned Element Locality

**Description**: When pinning elements in the Graph view's details panel, the element would jump back to `x:0, y:0, z:0` instead of freezing its coordinates precisely where it was grabbed.
**Fix**: Updated `use-graph-store.ts` inside the `togglePin` function. Now, before submitting the pin to DB or locking `fx/fy/fz`, it explicitly reads the ForceGraph3D engine `nodes` to find the exact *live layout* `x/y/z` coordinates of that node instead of the stale store variables.
**Verification**: Pinning a dragged element now immediately locks its actual onscreen coordinates.

## 3. Custom Attributes Not Editable

**Description**: When adding custom attributes to elements or relationships, they appeared on the data table but were missing from the Edit form modals because the modals were constrained to "Schema-only" attributes instead of any dynamically added project-level attributes.
**Fix**: Modified `edit-element-dialog.tsx` and `edit-relationship-dialog.tsx` to read `elementAttributes` and `relationshipAttributes` respectively from `useGraphStore()`. This maps iterating inputs for EVERY dynamically created attribute column in the project.
**Verification**: Verified all columns match inputs in both modals now.

## 4. Custom Project Creation Field

**Description**: Selecting a Custom / "Other" template when creating a new project would needlessly prompt the user for a "Custom Type Name".
**Fix**: Updated `new-project-dialog.tsx`. Stripped away the `customType` state and `<Input>` completely. Whenever "Other" is selected, the Project Type defaults strictly to string value `"Custom"`.
**Verification**: Selecting "Other / Custom" while creating a project no longer pushes the UI down with a redundant input block.

## Testing Strategy

- **app.test.ts**: Included a regression suite specifically proving `togglePin` intercepts live graph coordinates successfully.
